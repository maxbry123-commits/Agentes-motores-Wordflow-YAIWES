# Agent Skill Lab v0.1 Scope

**Status:** proposed
**Scope date:** 2026-07-30
**Stage:** deterministic compatibility proof

## Purpose

Version 0.1 will test one narrow product claim:

> A local, deterministic compatibility linter can identify useful Agent Skills,
> OpenClaw, and Hermes portability problems that a security-first scanner does not
> report.

Agent Skill Lab will complement established security scanners. It will not reproduce
their malware rules, risk scores, semantic analysis, or installation gates.

## Intended users

- skill authors checking a package before publication;
- reviewers checking a skill in a pull request;
- users comparing whether one skill package is usable on a target runtime;
- platform maintainers reviewing format and portability disagreements.

## Supported input

Version 0.1 accepts exactly one local skill directory.

It must:

- treat every inspected file as untrusted data;
- remain inside the selected directory after resolving paths;
- inspect files without importing or executing them;
- reject or explicitly report unsupported, escaping, or ambiguous paths;
- apply size and file-count limits before parsing content.

Remote repositories, URLs, archives, registries, and installed-skill discovery are
deferred.

## Initial target profiles

1. portable Agent Skills core;
2. OpenClaw runtime conventions;
3. Hermes Agent runtime conventions.

ClawHub and Hermes distribution surfaces may be reported only when the required
evidence is local and deterministic. NanoClaw, Codex, Claude Code, and other runtimes
are deferred until the first three profiles demonstrate user value.

## Version 0.1 rule families

The first implementation is limited to six evidence-backed rule families.

| ID | Rule family | Required result |
|---|---|---|
| `ASL-V001` | Portable metadata shape | Validate core fields and preserve namespaced platform extensions without silent information loss. |
| `ASL-V002` | Resource and symlink portability | Inventory links and referenced resources, detect escapes, and report transports or targets that may not preserve them. |
| `ASL-V003` | Runtime prerequisites | Report referenced commands, binaries, environment variables, and required runtime tools that are not explicitly declared. |
| `ASL-V004` | External context and permissions | Report assumptions about repository state, CI, network, credentials, filesystem access, or external services. |
| `ASL-V005` | Progressive disclosure | Report oversized or monolithic instructions when optional detail can be moved into focused local references. |
| `ASL-V006` | Privileged or persistent setup | Report installation, authentication, background-service, privilege, or persistence instructions that require explicit user approval. |

These families are derived from the completed `ASL-C004`, `ASL-C005`, and `ASL-C007`
manual baselines and the pinned SkillSpector 2.5.0 comparison. They are not a claim of
complete coverage.

## Finding contract

Every finding must include:

- stable rule identifier and rule version;
- evaluated target profile;
- severity and confidence;
- file path and source location when available;
- concise evidence;
- explanation of the compatibility impact;
- deterministic remediation;
- provenance of the rule;
- checks that were skipped, unsupported, or inconclusive.

The result vocabulary remains:

- `compatible`;
- `compatible_with_conditions`;
- `incompatible`;
- `unknown`;
- `not_applicable`.

No single safety or trust score will be produced.

## Outputs

The proof must produce:

- a concise terminal report for humans;
- a versioned JSON report for automation;
- deterministic exit codes for invalid input and configurable rule failures.

A Markdown exporter, GitHub Action, hosted interface, and automatic remediation are
deferred until the core rule output is stable.

## Safety and privacy requirements

The baseline inspector must:

- run locally;
- use no network access;
- require no LLM or external model;
- execute no inspected script, hook, installer, test, or command;
- access no ambient credential value;
- follow no URL found in inspected content;
- avoid importing inspected code;
- preserve explicit unknowns instead of guessing.

Security-scanner integration is optional and outside the baseline process.

## Explicit non-goals

Version 0.1 will not:

- compete with SkillSpector or another general security scanner;
- certify that a skill is safe;
- perform behavioral or sandbox execution;
- install, repair, rewrite, or publish skills;
- scan remote inputs;
- support every agent runtime;
- maintain a public registry;
- use an LLM to create baseline findings;
- hide platform-specific information behind a universal score.

## Validation set

The initial validation set contains:

- `ASL-C004` / `handoff`;
- `ASL-C005` / `autoreview`;
- `ASL-C007` / `llm-wiki`;
- small controlled fixtures for each rule family;
- up to three additional public packages chosen specifically to challenge the six
  rules, not to resume the broad 12-package baseline.

## Go or stop criteria

The compatibility proof proceeds to an alpha CLI only if:

1. all six rule families have deterministic fixtures;
2. repeated runs produce byte-stable JSON after excluding documented timestamps;
3. no inspected content is executed and no network access is required;
4. the three completed samples reproduce the expected evidence-backed findings;
5. false positives and unsupported cases are visible rather than silently filtered;
6. at least one independent author or maintainer confirms that a finding would change
   an authoring, review, or installation decision.

If these conditions fail, preserve the research artifact and stop implementation
before adding more platforms, scanners, or interfaces.

## Deferred decisions

The implementation language, package name, distribution channel, Markdown output,
GitHub integration, and user interface will be selected only after the rule contract
and fixtures are reviewed.

# Feedback and contributions

Issues, corrections, and research suggestions are welcome. This personal project does not currently accept unsolicited code or documentation pull requests. If that policy changes, each contribution's authorship and license will be recorded explicitly.

## Before proposing a change

1. Use only synthetic, self-authored, or clearly licensed inputs.
2. Do not copy restricted, unpublished, or third-party competition artifacts.
3. Keep scientific backends behind interfaces unless redistribution rights are explicit.
4. Label reconstructed evidence with `reconstructed: true`.
5. Distinguish a tested result from a proposed benchmark or future design.
6. Add or update tests for behavioral changes.
7. Update the capability ledger or reproducibility level if your change affects a public claim.

## Claim discipline

Use the smallest claim supported by the evidence:

- a unit test supports the tested contract, not general scientific correctness;
- a synthetic end-to-end run supports R2, not historical-score reproduction;
- an LLM explanation can motivate a hypothesis, not validate it;
- a deterministic supervisor scan can detect defined conditions, not prove universal compliance;
- one successful seed is not a stability estimate.

## Change records

Any future accepted contribution should use a small change record with a clear purpose, observable behavior, verification performed, and remaining limitations.

## Licensing

If external contributions are accepted in the future, their authorship and Apache-2.0 licensing will be agreed and recorded explicitly. Do not propose material whose ownership or redistribution terms are unclear.

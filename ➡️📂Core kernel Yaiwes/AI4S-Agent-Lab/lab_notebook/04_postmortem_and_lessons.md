# Postmortem and durable lessons

## What worked

### 1. Real measurements changed execution

Task1 treated throughput, mount readiness, and delivery reserve as runtime evidence rather than static configuration.

### 2. A scientific result changed the next generation

Task2’s current-target docking feedback altered fragment sampling in later rounds. A recoverable source-level single-toggle contrast and one positive cross-version score observation support this as the project’s clearest closed-loop research example. The source baseline lacks an independently scored platform run, and missing score-bound carriers and repeated equal-budget runs prevent a stable effect-size claim.

### 3. Version boundaries were eventually repaired

The post-competition audit separated scoring images, review packages, current source, and experimental history. This prevented later safety work from being retroactively credited with earlier scores.

### 4. Negative results remained inspectable

Proxy mismatch, more-complex regressions, seeded-vs-best differences, and the task4 penalty were retained as learning assets.

### 5. Delivery engineering became part of the method

Floors, time reserve, validation, atomic writes, and fallback protected usable outputs under uncertain infrastructure.

## What failed

### 1. The project initially overused a universal-Agent narrative

The four systems did not share enough runtime architecture to support it. The corrected description is “thin engineering core + four task-specific systems + common research discipline.”

### 2. Logs were not a unified evidence system

Call logs, stage records, tool output, validators, platform scores, and development ledgers existed at different layers. No single log proved the complete causal chain.

### 3. Model-brand attribution outran version evidence

Runtime configurations changed, and some highest-scoring versions lacked an immutable model/log/score binding. The corrected public story avoids unsupported attribution.

### 4. Multi-agent and memory concepts were ahead of implementation

Supervisor roles existed, but strong isolation and same-budget benefit were not demonstrated. Development documents persisted across sessions, but a runtime cross-run memory service did not.

### 5. Tool abstraction crossed the scientific boundary

Task4 packaged task-specific training and metric alignment inside tools. This was the most consequential design error.

## Rules carried forward

1. **Observation before action:** record what changed before proposing another experiment.
2. **Real tools before self-critique:** scientific measurements outrank model opinion.
3. **Same-scale promotion:** do not compare candidates through inconsistent evaluators.
4. **Floor before exploration:** protect a valid result first.
5. **Version before attribution:** bind claims to the object that actually earned them.
6. **Instrument, not hidden solution:** an Agent tool should expose a scientific primitive, not the benchmark answer.
7. **Questions are not memory facts:** unresolved Socratic prompts stay hypotheses.
8. **More agents require an ablation:** extra roles must justify cost and independence.
9. **A best seed is not a distribution:** report center, spread, and failures.
10. **Publication is a separate engineering task:** clean history, licenses, provenance, secrets, data rights, and executable verification all matter.

## Historical context vs personal research work

This repository has one identity: it is Wanrun Cong's personal research project. The historical competition experience supplies questions and bounded observations, but it does not determine ownership of the code and documentation developed here.

| Object | Treatment in this repository |
|---|---|
| Original code, tests, synthetic examples, and research documents | Created for this personal project under Wanrun Cong's direction, review, and publication responsibility |
| Historical rankings, scores, and review outcomes | Team-project context from the author's participation; not presented as an individual result |
| Reconstructed traces | Explanatory evidence with explicit reconstruction flags; never described as original logs |
| Original competition data, logs, submissions, and third-party payloads | Excluded; no ownership or redistribution right is implied |

The project's credibility should come from inspectable current work and precise claim boundaries, not from an implied institutional relationship.

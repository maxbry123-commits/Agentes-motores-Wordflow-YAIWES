# Workflow: full-autonomous

Full cycle without human pauses, with a mandatory final human gate.

## Trigger

- `project-config.yaml` has `mode: autonomous`.
- All materials (brief / research questions / guide / transcripts) are already in place — otherwise autonomous mode makes no sense.

## When applicable (repeated for emphasis)

- Auditing the work of an external agency.
- Desk research.
- Drafting key findings on existing transcripts.

Not applicable: a new project with a stakeholder (see `docs/modes.md`).

## Behavior

In contrast to `full-assistive`:

1. **No pauses.** The agent runs the entire pipeline without waiting for the researcher's reaction.
2. **All artifacts are written.** Nothing is skipped.
3. **`concerns.md` is mandatory.** At each step, explicitly record doubts and trade-offs in `4-output/concerns.md`. Structure: date / stage / the concern / what was done instead.
4. **`handoff.md` at the end.** A summary: list of all artifacts + a link to `concerns.md` + an explicit disclaimer "draft, requires review."
5. **Final human gate.** No publishing to docs, no sending anything externally happens without an explicit "published by the researcher after review" in chat.

## Sequence

See `full-assistive.md`. Differences:

- Everywhere it says "**Pause**" — do NOT pause. Move on.
- Everywhere it says "in chat: ..." — write a short note in `handoff.md` instead of a full chat dialogue.
- In chat — only a summary once per phase: "finished the preparation phase," "finished the analysis phase," "all done, read the handoff."

## Which steps matter most in autonomous mode

- **Verbatim validation of quotes** (in `09-flat-coding`): without a human to spot a fabrication, this check is the main defense against hallucinations.
- **`14-paradigmatic-model`**: always built — it's the structure for the final deliverable.
- **Disconfirming cases** (`15-disconfirm-triangulate`): without a researcher demanding "what's the counter-evidence?", the agent is prone to confirmation bias. Run an explicit search for disconfirming cases.
- **Anti-pattern check for the typology** (`16-typology`): automatic. If the typology fails the check (substituting demographics, non-exclusive categories) — don't include it in `handoff.md`; leave it only in `3-analysis/`.

## What must be in `handoff.md`

```markdown
# Handoff — {{project name}}

> ⚠️ This is a draft generated by an autonomous agent pass. It requires researcher review before going out externally.

## TL;DR

{{one sentence on the main point}}

## What was completed

| Stage | Artifact | Confidence |
|---|---|---|
| Brief | [[1-methodology/brief.md]] | high |
| Research questions | [[1-methodology/questions-and-hypotheses.md]] | high |
| ... |

## Key findings

(brief statements + links to `3-analysis/findings/F0X.md`)

## Concerns

(top 5 from `concerns.md`)

## What was NOT done

(if something was skipped — why)

## What the researcher should check first

(top 3 places where autonomous mode could realistically have gone wrong)
```

## Failure modes

- **All interviews from one segment.** Say in `handoff.md`: "the sample is one-sided; the typology/findings may not generalize."
- **A quote failed the verbatim check.** Don't insert it. In `concerns.md`: "claim X needed a quote from R0Y, but it isn't in the transcript verbatim — the claim is left as [interpretation]."
- **No disconfirming cases were found.** This does **not** mean "everything was confirmed." It means "a blind spot is possible." Flag it explicitly in `handoff.md`.
- **The paradigm model came together too neatly.** That's a bad sign — real data is usually contradictory. Re-check it.
